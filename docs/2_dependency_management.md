# 2. Dependency management

This project uses a modern Python dependency management approach combining [`pip-tools`](https://etc.com/jazzband/pip-tools) for production dependencies and `pyproject.toml` for development tools.

Dependencies are separated into two categories:
- **Production dependencies**: Managed via `requirements.in` → `requirements.txt` 
- **Development dependencies**: Managed via `pyproject.toml`

---

## 2.1 Overview of the dependency workflow

The project separates different types of dependencies:

- **`requirements.in`**: Production dependencies that your project needs to run (e.g. `requests`, `pandas`, `fastapi`).
- **`requirements.txt`**: Generated by `pip-tools`, contains all resolved production packages with pinned versions.
- **`pyproject.toml`**: Development tools and testing dependencies (e.g. `pre-commit`, `pytest`, `black`, `mypy`).

This approach provides:
- Clean separation between production and development dependencies
- Reproducible builds with pinned versions
- Optional installation of development tools
- Consistency across environments

---

## 2.2 Installation Workflow

To add dependencies, follow these steps based on the type:

### For Production Dependencies

1. **Add the dependency to `requirements.in`**
    
    For example, to add `requests`:
    
    ```
    # Core project dependencies go here
    # Development dependencies are in pyproject.toml [project.optional-dependencies.dev]
    requests
    pandas
    ```
    
    <aside>
    ⚠️
    
    Do not add version pins unless absolutely necessary. Let pip-tools resolve the version.
    
    </aside>
    
2. **Run the dependency script**
    
    Use the project's dependency script to resolve and install:
    
    ```bash
    ./scripts/dependency.sh
    ```
    
    **This will:**
    
    - Activate your virtual environment (from `.venv/`)
    - Install `pip-tools` if needed
    - Compile `requirements.txt` from `requirements.in`
    - Install all dependencies
    - Run `pip check` to ensure compatibility

3. **Commit the changes**
    
    Always commit both files:
    
    ```bash
    git add requirements.in requirements.txt
    git commit -m "Add requests dependency"
    ```

### For Development Dependencies

To add development tools (linters, formatters, testing tools):

1. **Add to `pyproject.toml`**
    
    Edit the `[project.optional-dependencies.dev]` section:
    
    ```toml
    [project.optional-dependencies]
    dev = [
        "pre-commit",
        "detect-secrets", 
        "nbstripout",
        "pytest",
        "pytest-cov",
        "black",
        "isort",
        "flake8",
        "mypy",
        "pip-tools",
        "your-new-tool",  # Add here
    ]
    ```

2. **Install the updated dependencies**
    
    ```bash
    pip install -e .[dev]
    ```

### Installation Options

- **Minimal (production only)**: `pip install -e .`
- **Full development setup**: `pip install -e .[dev]`
- **Using the script**: `./scripts/dependency.sh` (installs both)
---

## 2.4 Sanity Check

To manually verify that all installed dependencies are compatible, run:

```bash
pip check
```

This is automatically done by the setup script as well.

---

## 2.5 Summary of Rules

| ✅ Do This | ❌ Don't Do This |
| --- | --- |
| Add production deps to `requirements.in` | Don't run `pip install <package>` manually |
| Add dev tools to `pyproject.toml` | Don't edit `requirements.txt` by hand |
| Use `./scripts/dependency.sh` or `pip install -e .[dev]` | Don't mix production and dev dependencies |
| Commit both `requirements.in` and `requirements.txt` | Don't skip `pip check` or forget to compile |
| Use `pip install -e .` for minimal installs | Don't install dev tools in production |

## 2.6 Migration from Previous Setup

If you're updating from an older version of this template where all dependencies were in `requirements.in`:

1. **Identify development tools** in your current `requirements.in`
2. **Move them to `pyproject.toml`** in the `[project.optional-dependencies.dev]` section
3. **Keep only production dependencies** in `requirements.in`
4. **Regenerate `requirements.txt`** with `pip-compile requirements.in`
5. **Install dev dependencies** with `pip install -e .[dev]`
